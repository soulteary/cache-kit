# cache-kit v2.1.4

This patch updates the optional Redis packages to `go-redis/v9` v9.24.0 and
`redis-kit` v1.8.4. The module requires Go 1.27.4.

| Module | Previous | Updated |
| --- | --- | --- |
| `github.com/redis/go-redis/v9` | v9.23.0 | v9.24.0 |
| `github.com/soulteary/redis-kit` | v1.8.3 | v1.8.4 |

## Redis client compatibility

The upstream client changes exhausted dial retries, context-deadline error
matching and enforcement of `MaxActiveConns`. Review application retry,
timeout and pool settings against the
[go-redis v9.24.0 notes](https://github.com/redis/go-redis/releases/tag/v9.24.0).

For caller-owned clients, keep `PipelinePoolSize: -1` when a shared connection
budget is required, as described in the README. Cache constructors do not
reconfigure an existing client.

## Upgrade and rollback

```sh
go get github.com/soulteary/cache-kit/v2@v2.1.4
```

Existing cached values remain readable when upgrading from v2.1.3. The
root and in-memory TTL packages continue to use only the standard library.

To roll back, restore the application's previous `go.mod` and `go.sum`, then
rebuild. Downgrading cache-kit alone can leave newer Redis dependencies
selected by other requirements in the application.
